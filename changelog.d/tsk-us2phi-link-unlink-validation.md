### Fixed
- ``CollectionStore.unlink`` now validates ``link_type`` and ``ext_id`` with the same guards as ``link``, returning ``ValueError`` for unknown types and non-string or empty ids. Previously ``unlink`` accepted any ``link_type`` and any ``ext_id``, so a caller could pass a bogus type or an id that ``link`` would have rejected and the DELETE would silently match no rows. The project filter on ``CollectionStore.list`` now strips the ``project`` argument before comparing it to stored link ids, so a collection linked with surrounding whitespace can be found again by passing the same padded project id.
