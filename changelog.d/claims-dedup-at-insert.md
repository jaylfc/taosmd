### Fixed

- `ClaimStore.add_claim` now dedups at insert (issue #653): a claim whose normalized text already exists merges its `archive_span_ids` into the existing row instead of inserting a duplicate. A multi-day shadow deployment measured 10,063 rows for 3,915 distinct texts — the same sentence re-extracted every turn piled up a fresh row each time, inflating the corpus and skewing any hallucination-rate metric computed over it. Merging is zero-loss (no row or span is dropped) and never resets a verification status the verify pass already set. A `claims_norm_dedup` migration adds the `norm` column, backfills it for pre-existing rows, and indexes it; the index is not UNIQUE because legacy databases legitimately contain duplicate rows that are never deleted.
