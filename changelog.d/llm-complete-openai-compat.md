### Added

- The librarian stages (session enrichment, crystallize, reflect, query expansion, and the LLM reranker) now speak OpenAI-compatible servers as well as Ollama. They previously hardcoded Ollama's native `/api/generate`, so pointing `llm_url` at a llama.cpp, vLLM, or Ollama-`/v1` endpoint made every stage 404 and silently degrade to heuristics; the index result still reported `enriched: 1`, so the quality drop was invisible downstream. Selection is by endpoint probing (`/api/version` answers, else `/v1/models`; if neither signature answers, the historical Ollama default is kept), cached per base URL; `llm_complete.set_api_family` pins a dialect explicitly for callers that need it. Reasoning backends that answer OpenAI calls with `content=null` fall back to the `reasoning` field instead of returning empty text.
