### Added

- `taosmd.answer_context()`, `POST /answer-context` and the MCP tool `memory_answer_context` build the context an agent answers from: hits from the same retrieval and scoping as search, hits grouped by session; every candidate session first gets its hit turns and their neighbours, then the budget left grows sessions to the whole session in rank order. The result is session blocks headed by the session date, oldest first, under a token budget. A block that does not fit is dropped whole and reported (`sessions_dropped`, `dropped`), never cut. `taosmd.default_budget_tokens()` gives a starting budget from the model window.
- `ingest` (library, `POST /ingest`, MCP `memory_ingest`) accepts optional `session_id`, `turn_index` and `session_date` for a turn and stores them with new rows, so neighbours and session dates can be rebuilt. Existing rows are not rewritten; a hit on a row without them stands alone.
- The LongMemEval and LoCoMo runners take `--context product` (with `--reader-ctx-tokens`): the haystack goes in through `taosmd.ingest` and the context comes only from `taosmd.answer_context`, with no character cut and no verify pass. The per-question context hash, tokens used and dropped sessions are written to the results.
