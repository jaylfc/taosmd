### Fixed

- `CollectionStore.unlink` now validates `link_type` and `ext_id` with the same guards as `link`, raising `ValueError` for unknown link types and non-string or empty ids. Previously `unlink` accepted any `link_type` and any `ext_id`, so a caller could pass a bogus type or an id that `link` would have rejected and the DELETE would silently match no rows. `unlink` also strips `ext_id` before deleting, so a link added with surrounding whitespace can be removed with the same padded input, matching `link`'s storage spelling.
- `CollectionStore.list`'s `project` filter now normalises with `project.strip() if isinstance(project, str) else project` (preserving the `isinstance` guard its `link`/`unlink` siblings use). A non-string `project` (e.g. an int from a programmatic caller) previously reached the `==` comparison harmlessly and returned no matches; the strip-without-guard variant added in PR #466 crashed with `AttributeError` on `.strip()`, and the guard restores the pre-existing no-crash behavior while still stripping whitespace from string inputs.
